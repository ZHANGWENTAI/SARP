# SARP 的任务接入与泛化验证

SARP 是 Structure-Aware Reasoning Prototype（结构感知推理原型）。它接收任务适配器提供的计算图和算子，生成实际处理范围及节点分组，选择方案后执行计算。

## 从原型接口到可接入的执行器

原先的 `Task`、`Planner` 和 `Runtime` 已能描述、比较和派发任务，但每个新领域还需要编写 `execute` 方法，并在其中解释计算图、处理缓存与执行分组。

`structure_aware/sarp.py` 将计算图解释、缓存管理及分组执行实现为计算图执行器。电子表格与图像任务的适配器都没有 `execute` 方法，也没有范围传播、表达式合并或缓存失效算法。它们只提供：

1. `Graph`：输入、节点、依赖、所需输出和任务命名空间。
2. `Operation`：具体计算函数、是否无副作用、算子版本。
3. 节点参数和计算权重，用于判断表达式一致性与比较方案代价。

执行器自动完成依赖排序、输入内容指纹、变化传播、输出祖先筛选、缓存维护和分组执行，并调用`core.Planner` 比较完整执行、范围收缩、节点合并及二者组合。规划器中没有新增表格或图像专用分支。

`Session` 保存一次任务执行后的有效状态。新调用会校验输入内容、节点参数、依赖关系、算子版本和任务命名空间；发生变化的节点及其下游重新计算，其他有效结果可以复用。输入采用内容指纹，原地修改数组也能被检测；数组在执行和缓存时按只读值处理。

## 可泛化的范围与接入契约

“可接入新任务”与“每个任务都能加速”是两个问题。给出合法计算图和算子后，SARP 能生成方案并执行；实际收益取决于是否有局部变化、重复表达式或其他可调整结构。没有代价收益时，自动选案保留完整执行，规划过程本身仍有耗时。

声明式接入适用于能够展开为有限有向无环图的计算。循环可展开成步骤或封装为算子；需要有环更新、训练反向语义或近似预算的任务，可通过 `register_backend` 和 `execute_task` 使用执行后端。动态图、逻辑训练和视频预算可通过后端接口接入。两个新实例验证的是精确范围收缩与节点合并，没有把近似预算强行用于这些任务。

无副作用的算子要显式声明 `pure=True`。这表示其结果由输入、参数和版本决定，不修改输入，不读取未声明的可变状态，合并或跳过它不会改变外部行为。随机数、文件写入、计数更新等操作默认不得跨次缓存或合并；有执行次序要求的操作还需声明相应依赖。模型权重等隐藏状态应放入输入、参数或算子版本。系统依据这些契约保证执行安排，不会自动证明任意外部代码的数学性质。

有副作用的节点及其依赖始终保留；此类任务验证失败时不自动重放，以免重复外部操作。每个调用方使用自己的 `Session`，并发访问同一会话需要调用方同步。

## 最小接入代码

```python
import numpy as np
from structure_aware.sarp import Graph, Node, Operation, SARP, Session

class MyAdapter:
    operations = {
        "square": Operation(lambda x: x * x, pure=True, version="1"),
    }

    def build(self, x):
        return Graph(
            namespace="my-task-v1",
            inputs={"input": x},
            nodes=(
                Node("left", "square", ("input",), work=x.size),
                Node("right", "square", ("input",), work=x.size),
            ),
            outputs=("left", "right"),
        )

runtime, session = SARP(), Session()
data = np.arange(8192, dtype=float)
first = runtime.run(MyAdapter(), data, session=session)
second = runtime.run(MyAdapter(), data, session=session)
# first 合并两次相同平方计算；second 校验输入后复用已有结果。
```

适配器无需给出需要重算的节点列表，也无需预先合并节点。输入、依赖和算子定义是描述性信息，执行优化由运行时完成。

## 样例一：电子表格公式重算

任务模拟业务报表：12个区域，每个区域有65536条收入和支出记录；5个报表视图分别计算税后利润指标。公式包含减法、乘法、SUM、缩放以及单元格依赖。适配器解析公式的受限语法树，不执行 Python `eval`。

例如，两个视图都包含 `SUM((Revenue - Expense) * 0.9)`。它们的公共表达式可合并；某些区域收入更新后，只需重算相关公式。适配器提供公式及基本算子，依赖分析与优化均由SARP执行。

部分更新条件修改12个区域中的2个收入范围，模型和其他输入不变。自动方案选择范围收缩与节点合并：算子调用由540次降至36次，减少93.3%；加权代价下降96.7%，在线耗时加速 **1.37±0.03倍**。输出与直接业务公式逐项比较，最大误差为0。

## 样例二：图像处理流水线

任务对6张192×192的RGB图像生成边缘图、阈值掩码和增强预览。每条分支包含灰度变换和两轮高斯滤波，再执行Sobel边缘、阈值或亮度处理。

多个输出需要相同的灰度与滤波结果，因此可以合并这部分计算；只有一张图像变化时，其他图像的输出保持有效。适配器提供图像算子和流水线描述，执行器负责分组及缓存。

部分更新条件修改6张图像中的1张。自动方案选择范围收缩与节点合并：算子调用由54次降至5次，减少90.7%；加权代价下降92.5%，在线耗时加速 **3.65±0.05倍**。边缘、掩码和预览均与直接流水线逐元素一致，最大误差为0。

## 如何运行与检查

在仓库目录执行：

```bash
python3 examples/sarp_walkthrough.py
python3 -m structure_aware.generalization --quick --output results/new_quick_demo
python3 -m structure_aware.generalization --output results/new_full_demo
python3 -m structure_aware.generalization --audit results/new_full_demo
```

逐步示例会导出 `examples/generalization_spreadsheet.json` 和 `examples/generalization_image_pipeline.json`，列出节点、依赖、必要处理集合、各方案分组、算子调用和结果摘要。

完整结果保存于 `results/generalization_full_20261030/`：5个输入种子，每条件预热2次、计时7次，按种子打乱方案执行次序。两类任务各有4种条件、5种执行模式，共200条条件记录、1400次计时运行，全部结果逐项一致。

计时包含适配器构图、输入复制、内容指纹、缓存检查、方案生成与比较、执行及结果组装。初始缓存构建属于预处理，另存其耗时。为使方案从相同状态比较，实验在计时外恢复会话字典；原始数组为只读状态。参考核验单独计时。加速比先对每个种子的7次耗时取均值，再计算该种子的参考耗时与方案耗时之比，最后报告5个种子的均值与样本标准差。

保存文件包括输入数组、公式与变化说明、计算结果摘要、逐次计时、候选方案、选中方案、源文件快照和环境信息。核验程序检查条件覆盖、文件摘要、选案代价、重复次数及汇总一致性，并从保存的输入重新计算直接参考结果。

测试覆盖输入原地更新、节点参数和算子版本变化、任务命名空间隔离、依赖排序、无效图、有副作用的操作、缓存、结果回退及原有后端接入。高斯滤波另与独立二维卷积计算核对。
